# Python 组件内联装配指导

本 Skill 用于指导 agent 将两个独立的 Python 组件脚本组合成一个"总装脚本"，并严格满足以下约束：

- 不允许跨文件类导入（例如 `from a import A`）
- 不允许动态加载（例如 `importlib`、`exec`、`eval`、运行时路径加载）
- 必须把两个源脚本中的建模逻辑内联到同一个总装 `.py` 文件

当用户提出"将两个 python 组件组装/组合/合并到一起"时，必须先调用本 Skill，再进行实现。

## 何时必须调用

- 用户要求把两个或多个组件脚本装配成一个总装
- 用户明确要求"代码内联""单文件交付""不做跨文件导入"
- 用户要求把现有组件建模逻辑合并为统一入口输出
- 用户要求总装里可统一控制参数并同时生成多个子构件

## 强制约束

1. 总装文件中不得出现对组件源文件的导入依赖  
2. 总装文件中不得出现 `importlib`、`exec`、`eval`、动态路径加载  
3. 两个组件的核心建模代码必须保留在总装文件中，且可直接执行  
4. 若存在同名函数、类、参数，必须在总装文件内完成命名消歧  
5. 总装入口必须清晰，能够一次性生成全部目标构件  

## 标准工作流

### 1) 盘点与解耦

- 提取两个源文件的依赖、常量、工具函数、参数入口、几何生成入口
- 标记冲突项：同名函数、同名类、同名全局变量、同名参数
- 标记耦合项：只在单文件内使用的私有辅助逻辑

### 2) 内联迁移

- 以"复制并重命名冲突对象"为原则，把两个脚本建模逻辑迁移到总装文件
- 将公共工具函数收敛为统一实现，或按前缀拆分（如 `comp_a_*`、`comp_b_*`）
- 保持原建模语义不变，优先保证几何结果一致

### 3) 统一参数接口

- 定义总装参数入口，分别映射到组件 A/B 的参数
- 对参数做基础校验（非负、范围、类型、几何有效性）
- 通过总装入口统一触发 A/B 生成逻辑

### 4) 总装组合输出

- 在同一脚本中生成组件 A、组件 B
- 在总装层处理相对定位（平移/旋转/镜像）
- 合并输出（组合体或并列输出），并保持可单独调试各子构件

### 5) 回归校验

- 对比内联前后关键尺寸与拓扑关系
- 验证参数变化时 A/B 均可稳定重建
- 验证脚本离开源组件文件后可独立运行

## 推荐代码组织

按以下顺序组织总装文件：

1. 公共 import 与常量  
2. 组件 A 内联区（参数处理 + 几何构建）  
3. 组件 B 内联区（参数处理 + 几何构建）  
4. 总装定位与组合区  
5. 统一入口（例如 `build_assembly(params)`）  

不同结构区之间保持物理分隔（空行或分段标识），确保可维护性。

## 冲突处理规则

- 同名函数：按组件前缀重命名，避免覆盖
- 同名类：优先重命名类名并同步调用点
- 同名参数：在总装入口采用命名空间（如 `a_radius`、`b_radius`）
- 同名全局常量：改为局部常量或前缀化常量

## 禁止做法清单

- `from component_a import *`
- `from component_b import SomeClass`
- `importlib.import_module(...)`
- 运行时读取外部脚本后 `exec(...)`
- 通过字符串反射调用外部组件逻辑

## 交付检查清单

- [ ] 只有一个总装 `.py` 文件可独立运行
- [ ] 两个组件建模逻辑均已内联
- [ ] 无跨文件类导入
- [ ] 无动态加载与执行
- [ ] 参数接口统一且无命名冲突
- [ ] 总装输出包含两个目标构件且定位正确
