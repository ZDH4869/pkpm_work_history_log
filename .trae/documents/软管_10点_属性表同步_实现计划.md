## 一、需求概述

1. 用户通过 MultiPointPlace 光标交互放置 **恰好 10 个**控制点
2. 放置完成后，30 个独立 XYZ 坐标参数加载到属性表中（起点X/Y/Z、中间点1~8 X/Y/Z、终点X/Y/Z），按点分组
3. 用户后续**只能通过属性表**修改坐标，属性表值为准

## 二、核心架构

**保持函数式 P3DData + MultiPointPlace 结构不变**，新增：

- 30 个独立 XYZ 参数（`obvious=True`，`group='起点坐标'` 等）
- 1 个隐藏参数 `_关键点哈希`（`obvious=False`）用于同步追踪
- 1 个辅助函数 `_hash_points()` 用于生成哈希指纹

**同步机制**：哈希比对法

```
关键点变化（MultiPointPlace）→ 哈希不匹配 → 同步到独立参数 → 更新哈希
独立参数变化（属性表编辑）→ 哈希不变 → 不触发同步 → 独立参数值被保留
```

**数据流**：`独立XYZ参数` 始终是几何计算的真实数据源，`关键点` 仅用于初始交互放置。

在 `_build_rounded_path` 函数之后（约第 296 行）、`def wsl(data):` 之前插入：

```python
def _hash_points(points):
    """生成 Vec3 列表的稳定字符串哈希，用于检测关键点是否变化"""
    parts = []
    for p in points:
        parts.append(f"{round(p.x, 6):.6f},{round(p.y, 6):.6f},{round(p.z, 6):.6f}")
    return "|".join(parts)
```

## 四、边界情况处理

| 场景 | 行为 |
|------|------|
| 首次运行（默认值） | 哈希匹配初始值，不触发同步，几何体用默认坐标构建 |
| 用户放置恰好 10 个点 | 哈希不匹配 → 触发同步 → 独立参数更新 → 几何体重建 |
| 用户放置少于 10 个点 | `len(KeyPoint)==10` 守护 → 跳过同步 → 独立参数保持上次值 |
| 用户在属性表修改坐标 | 哈希不变 → 跳过同步 → 编辑值直接用于几何计算 |
| 属性表修改后再用 MultiPointPlace | 哈希变化 → 同步覆盖独立参数 → MultiPointPlace 值为准 |
